  git history confirms the identical failure hit both run 1 (`c656c7a`) and run 2

  written into `tdd-engineer.md`/`tecnologia_qa.md` — so it was lost the moment this
  session's reset regenerated `setup.ts` from scratch. `backend-implementer` correctly
  refused to fix it itself (out of its writable scope, flagged it instead of silently
  patching test infra) — good adherence to scope boundaries.
- **Fix applied** (as tdd-engineer, since `setup.ts` is that agent's artifact):
  `happyDOM.settings.fetch.disableSameOriginPolicy = true`, restored verbatim from
  `c3fcaf8`'s version. Re-ran: 22/22 backend tests green.
- **Process fix, so it survives the next reset too**: added a new mandatory section to
  `tdd-engineer.md` ("`src/backend/tests/setup.ts` must disable happy-dom's same-origin
  policy") documenting this exact snippet as required content the first time `setup.ts` is
  created — not just a memory of what happened, a durable instruction. This is a 5th
  process gap found and closed this session, on top of the 4 already fixed.
